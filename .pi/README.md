## Как запускать

**`-a` обязателен.** Без него в неинтерактивном режиме Pi игнорирует ВЕСЬ проектный
`.pi/`: не читает `settings.json` (уходит в чужого провайдера — проверено, ушёл в OpenAI)
и не грузит сторожа. Проектные ресурсы требуют доверия к проекту, а `-p` доверие
не спрашивает и по умолчанию их отбрасывает.

`-e .pi/extensions/guard.ts` добавляем второй страховкой: он грузит сторожа
независимо от доверия. Проверено, что вместе они не конфликтуют.

**Авторская задача — пишет новый файл, оболочка не нужна.** Самый безопасный режим:
```
pi -a -e .pi/extensions/guard.ts -xt bash -p "$(cat panel/TASK-waiting.md)"
```

**Задача с прогоном проверок:**
```
pi -a -e .pi/extensions/guard.ts -p "$(cat panel/TASK-waiting.md)"
```

**Разбор без права писать:**
```
pi -a -e .pi/extensions/guard.ts -t read,grep,find,ls -p "..."
```

**Интерактив** (доверие спрашивается один раз, дальше живёт в `~/.pi/agent/trust.json`):
```
pi
```

Полезные флаги: `--mode json` — поток событий построчным JSON; `-c` — продолжить прошлую
сессию; `--model <id>` — разовая смена модели; `-nc` — не подгружать `AGENTS.md`
(имеет смысл для чисто кодовых задач: корневой `AGENTS.md` — это протокол Direction OS,
он вставляется в промпт целиком и для написания парсера только мешает).

## Что делает сторож

`extensions/guard.ts` перехватывает вызов инструмента ДО выполнения и блокирует его.

| Правило | Поведение |
|---|---|
| `write` / `edit` | разрешены только в `panel/`, `os2/`, `.pi/` |
| `write` / `edit` вне репозитория или путь не разобран | блок |
| `read` | всё, кроме `archive/` |
| `bash` | блок на `git commit/push/add/reset/checkout/…`, `rm -r`, `sed -i`, редиректы и `cp/mv/rm/tee` в `live/ os/ archive/`, глобальную установку npm |
| корень репозитория не найден | блокируется всё |

Проверка логики сторожа, 21 случай, без единого обращения к модели:
```
node .pi/extensions/guard.test.cjs
```

**Сквозная проверка 2026-08-06 — забор настоящий, а не послушание.** Запрос на чтение
`archive/` был заблокирован даже с флагом `-nc`, то есть когда `AGENTS.md` не загружен
и правило про архив модели вообще неизвестно; Pi назвал причиной `guard.ts`. Запрос
на запись нового файла в `os/` тоже заблокирован — `PROBE.md` не создан.

**Честная граница.** По путям сторож надёжен: проверка идёт по разрешённому корню, а не
по списку запрещённых, и обход через `..` и абсолютные пути закрыт. По оболочке — нет:
`python -c "open('live/x','w')"` он не поймает. Настоящая изоляция — не давать `bash`
там, где он не нужен (`-xt bash`), и запускать Pi с рабочим каталогом внутри `panel/`.
Сторож — это ремень безопасности, а не сейф, и относиться к нему надо так.

## Чего Pi не делает

Не трогает `live/**` и `os/**` — действующий workflow меняется только применением RESULT.
Не коммитит и не пушит. Не сочиняет обращённый к владельцу русский текст. Не пишет
эталоны собственных тестов. Не решает, что «выглядит правильно»: приёмка — код возврата.

Известное про сам инструмент: правка существующих файлов у Pi ошибается в 3–6% вызовов,
поэтому задачи ставятся как «создай новый файл целиком», а не «поправь строку».
