# Pi на этом репозитории

Pi (`@earendil-works/pi-coding-agent`, установлен 0.83.0) — исполнитель механической работы.
Claude Code и Codex зовут его из консоли; владелец зовёт его сам.

## Что нужно один раз — делает владелец

Ключ Qwen Token Plan. Ни одна сессия ключ не вводит и не читает.

```
pi
/login
```
выбрать **Qwen Token Plan**, вставить ключ. Он ляжет в `~/.pi/agent/auth.json`.

Альтернатива без интерактива — переменная окружения `QWEN_TOKEN_PLAN_API_KEY`.

Проверка, что всё встало:
```
pi -p "ответь одним словом: готов"
```

## Модели этого плана

Провайдер `qwen-token-plan` даёт пятнадцать моделей, не только Qwen:

| Модель | Контекст | Для чего |
|---|---|---|
| `qwen3.7-plus` | 1M | по умолчанию: обычная механика |

| `glm-5.2` | 1M | код, сильная альтернатива |
| `deepseek-v4-pro`, `deepseek-v4-flash` | 1M | длинные разборы |

Переключение в сессии — `/model`, разово — `--model glm-5.2`.
Расход кредитов по моделям в пакете не описан: смотри футер сессии.

## Как запускать

Сторож `extensions/guard.ts` подключается **явным `-e`**. Без этого в неинтерактивном
режиме он не загрузится: проектные расширения требуют доверия к проекту, а `-p` доверие
не спрашивает и по умолчанию проектные ресурсы игнорирует.

**Авторская задача — пишет новый файл, оболочка не нужна.** Самый безопасный режим:
```
pi -e .pi/extensions/guard.ts -xt bash -p "$(cat tools/osctl/tasks/step-01.md)"
```

**Задача с прогоном проверок:**
```
pi -e .pi/extensions/guard.ts -p "$(cat tools/osctl/tasks/step-01.md)"
```

**Разбор без права писать:**
```
pi -e .pi/extensions/guard.ts -t read,grep,find,ls -p "..."
```

**Интерактив:**
```
pi -e .pi/extensions/guard.ts
```

Полезные флаги: `--mode json` — поток событий построчным JSON; `-c` — продолжить прошлую
сессию; `--model <id>` — разовая смена модели; `-nc` — не подгружать `AGENTS.md`
(имеет смысл для чисто кодовых задач: корневой `AGENTS.md` — это протокол Direction OS,
он вставляется в промпт целиком и для написания парсера только мешает).

## Что делает сторож

`extensions/guard.ts` перехватывает вызов инструмента ДО выполнения и блокирует его.

| Правило | Поведение |
|---|---|
| `write` / `edit` | разрешены только в `tools/`, `os2/`, `.pi/` |
| `write` / `edit` вне репозитория или путь не разобран | блок |
| `read` | всё, кроме `archive/` |
| `bash` | блок на `git commit/push/add/reset/checkout/…`, `rm -r`, `sed -i`, редиректы и `cp/mv/rm/tee` в `live/ os/ archive/`, глобальную установку npm |
| корень репозитория не найден | блокируется всё |

Проверка сторожа, 21 случай, без единого обращения к модели:
```
node .pi/extensions/guard.test.cjs
```

**Честная граница.** По путям сторож надёжен: проверка идёт по разрешённому корню, а не
по списку запрещённых, и обход через `..` и абсолютные пути закрыт. По оболочке — нет:
`python -c "open('live/x','w')"` он не поймает. Настоящая изоляция — не давать `bash`
там, где он не нужен (`-xt bash`), и запускать Pi с рабочим каталогом внутри `tools/`.
Сторож — это ремень безопасности, а не сейф, и относиться к нему надо так.

## Чего Pi не делает

Не трогает `live/**` и `os/**` — действующий workflow меняется только применением RESULT.
Не коммитит и не пушит. Не сочиняет обращённый к владельцу русский текст. Не пишет
эталоны собственных тестов. Не решает, что «выглядит правильно»: приёмка — код возврата.

Известное про сам инструмент: правка существующих файлов у Pi ошибается в 3–6% вызовов,
поэтому задачи ставятся как «создай новый файл целиком», а не «поправь строку».
