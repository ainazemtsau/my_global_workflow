# Workflow 2.0 — основание

Это спека основания, а не план работ. Переделка идёт отдельными чатами;
каждый из них начинает с этого файла и с `panel/PLAN.md`.

Собрано из измеренных отказов текущей версии, не из вкусов. Каждое решение ниже
названо вместе с тем, что именно оно чинит.

## 1. Три закона

**Закон 1. Состояние меняется только командой, никогда правкой файла.**
Агент не открывает файл состояния на запись. Он вызывает команду и передаёт ей
значения. Куда и в каком порядке лечь — знает команда, а не агент.

**Закон 2. Команда не разбирает текст, она принимает параметры.**
Скрипт никогда не ищет в документе место для вставки. Он адресуется по имени поля
и заменяет значение целиком. Если поле надо изменить — вызывающий приносит новое
значение полностью.

**Закон 3. Один предмет — один маленький файл.**
Не потому что так красивее, а потому что закон 2 иначе неисполним: чтобы не искать
место в тексте, у текста не должно быть места, которое надо искать.

## 2. Что именно это чинит

| Отказ, измеренный в текущей версии | Каким законом закрыт |
|---|---|
| Модель дописала запись в конец журнала вместо начала | 1 — порядок знает команда |
| Одно двоеточие в прозе валит разбор всего `NOW.md` | 3 — проза лежит в теле, разбор её не касается |
| 120 коммитов в неделю в один файл, параллельные ноги дерутся | 3 — каждый правит свой файл |
| Обязательное поле `started:` встречается **ноль раз** в обоих живых `NOW.md` | 1 — поле пишет команда, а не память агента |
| В шапках нарядов заведены самодельные ключи `exit_decided_2026_08_06`, `warning_2026_08_06` | 1 — команда принимает только известные поля |
| Две сессии в один день на одну задачу, 29 из 29 активных дней с несколькими сессиями | §5 слоты |
| Журнал не может сказать «эту ногу перебило вот этой» | §4 статус `superseded` |

## 3. Инструмент

Один вход: `python osctl.py <предмет> <действие> [--параметры]`.

```
osctl task close   --id t-house-2 --evidence history/2026-08-07-....md
osctl call issue   --id c-... --for t-house-6 --track сцена --to executor
osctl call status  --id c-... --set blocked --unblock-when "..."
osctl card set     --id t-house-2 --field status --value done
osctl card note    --id t-house-2 --block note --text "..."
osctl question add --text "..." --answer-by "перед копанием" --who владелец
osctl slot claim   --slot 2 --for c-...
osctl slot release --slot 2
osctl show         --id t-house-2
osctl find         --text "тоннель"
osctl check        --direction indie-game-development
```

Правила инструмента:

- **Известные поля только.** Неизвестное имя поля — отказ с перечислением известных.
  Самодельные ключи в шапке становятся невозможны.
- **Никогда не вставляет внутрь текста.** Только целое значение целого поля.
- **Пишет атомарно.** Записал во временный файл, перечитал, проверил, переименовал.
  Не прошло — исходный файл не тронут, и на выходе явная ошибка.
- **Ничего не оценивает.** Не решает, готово ли, правильно ли, достаточно ли.
  Это работа ИИ и владельца, а не скрипта.

**Журнал перестаёт быть рукописным файлом.** Тот отказ с записью в конец лечится
не аккуратностью, а тем, что писать туда руками больше некому: журнал —
это `git log` плюс поле в карточке, и порядок в нём не от кого зависеть.

## 4. Карточка

Один предмет — задача, наряд, узел, запись, вопрос, решение, ставка — один файл.

```markdown
---
id: t-house-2
kind: task
bet: g-1d84
track: дом
order: 5
status: open
---

## goal
Место, где груз не проходит просто так

## done_when
В доме есть хотя бы одно место, где груз не проходит просто так…

## description
Игроку надо решать: повернуть груз или зайти иначе.
```

- Между `---` только короткие поля: строка без переносов до 120 символов, число,
  булево, дата, пусто. Всё длинное — в тело блоком `## имя`.
- Тело — обычный markdown, читаемый глазами. Скрипт его не разбирает: он режет
  по строкам `## ` и заменяет блок целиком.
- Последняя строка — `END_OF_FILE: <путь>`. Обрезанный при передаче файл виден.

Формат уже доказан: конвертер раскладывает нынешний `NOW.md` на 48 карточек
и собирает обратно байт в байт (`panel/cards.py`, приёмка `verify.py 01a`).

**Терминальные статусы**, которых сегодня нет: `superseded` с обязательными
`superseded_by` и `at`. Без него нельзя записать, что одну ногу перебило другой —
дыра уже была залогирована во `FRICTION.md` 27 июля с пометкой «ждём второго случая»;
6 августа стало вторым.

## 5. Раскладка папок

```
live/<направление>/
  NOW.md            указатель: какая ставка, лимит полос, прогноз. ~30 строк, расти не может
  cards/            ЖИВОЕ — то, что сейчас в работе
  cards/closed/     ЗАКРЫТОЕ — тот же формат, та же команда читает
  history/2026-08/  отчёты по месяцам
  knowledge/
  work/
```

Живая папка не растёт: закрытая карточка переезжает в `closed/` командой,
а не остаётся числиться. Достать из закрытого просто — формат тот же,
`osctl show --id …` и `osctl find --text …` смотрят в обе папки.

Списков нет нигде. «Какие задачи в полосе дом» — это «все карточки с `track: дом`».
Списка никто не пишет, значит нечему разойтись.

## 6. Слоты

Ровно N рабочих копий с именами. Доска ключей лежит **вне репозитория**, поэтому
её видно независимо от того, кто что запушил — именно эта слепота была корнем
столкновения 6 августа.

Ключевое: **аренда называет, подо что взята** — id наряда. Тогда вторая заявка на
тот же наряд отбивается в момент захвата, и разрыв во времени перестаёт иметь
значение. Шестого августа между двумя ногами было 5 часов 48 минут: обычная
аренда «занято сейчас» к тому моменту была бы снята и не помогла бы.

Слот нельзя вернуть, не слив работу в `main`. Интеграция перестаёт быть отдельным
поступком, о котором можно забыть.

Точная схема доски — после разбора того, как это уже сделано в GasCoopGame:
там механизм работает, и изобретать заново нечего.

## 7. Проверка и запасной выход

Три уровня, и ни один не судит содержание:

1. **Каждая запись проверяет себя.** Записал — перечитал — шапка разбирается,
   `id` совпадает с именем файла, хвост на месте. Нет — откат и явная ошибка.
2. **`osctl check`** — отдельный прогон по всему направлению. Сообщает только
   механические факты: что не разбирается, у чего нет хвоста, какая ссылка никуда
   не ведёт. Не «правильно ли», а «читается ли».
3. **Глаза.** Ассистент открывает получившийся файл и смотрит. Это не запасной
   вариант на крайний случай, а нормальный последний шаг: смысл судит ИИ и владелец,
   скрипт судит только байты.

## 8. Переносимость

Python 3 и стандартная библиотека плюс `PyYAML`. Ни PowerShell, ни `.cmd`,
ни `.sh` — вызов одинаков на Windows и на Mac:

```
python osctl.py task close --id t-house-2
```

Пути только через `pathlib`, файлы только в UTF-8 с явным указанием, переводы
строк не навязываются. Никаких вызовов оболочки внутри — кроме `git`,
который есть везде одинаково.

## 9. Чего сознательно не делаем

- **Никаких полей, которые агент пишет о себе** в духе «взято мной в 13:51».
  Такое поле уже есть — `started:` — и его соблюдаемость нулевая. Защита на
  честности агента это не защита.
- **Никаких скриптов-судей.** Проверка смысла, полноты и достаточности остаётся
  за ИИ и владельцем. Скрипт устанавливает только объективные факты.
- **Никакой базы данных как источника правды.** Markdown в git — единственный
  авторитет; всё остальное кэш, который можно снести и построить заново.
- **Ничего, что красное в покое.** Владелец пушит руками и забывает; сигнал,
  горящий каждый день, перестаёт быть сигналом.

## 10. Порядок

1. `osctl` с командами чтения и `check` — ничего не меняет, но уже видно состояние.
2. Формат карточки закрепляется, конвертер переводит живое направление.
3. Команды записи, по одной: сначала те, что закрывают задачу и меняют статус.
4. Слоты и уборка флота.
5. Панель показывает всё это; разделы идут по `panel/PLAN.md`.
