# Workflow 2.0 — основание

Это спека основания, а не план работ. Переделка идёт отдельными чатами;
каждый из них начинает с этого файла и с `panel/PLAN.md`.

Собрано из измеренных отказов текущей версии, не из вкусов. Каждое решение ниже
названо вместе с тем, что именно оно чинит.

## 1. Три закона

**Закон 1. Состояние меняется только командой, никогда правкой файла.**
Агент не открывает файл состояния на запись. Он вызывает команду и передаёт ей
значения. Куда и в каком порядке лечь — знает команда, а не агент.

**Закон 2. Команда не разбирает текст, она принимает параметры.**
Скрипт никогда не ищет в документе место для вставки. Он адресуется по имени поля
и заменяет значение целиком. Если поле надо изменить — вызывающий приносит новое
значение полностью.

**Закон 3. Один предмет — один маленький файл.**
Не потому что так красивее, а потому что закон 2 иначе неисполним: чтобы не искать
место в тексте, у текста не должно быть места, которое надо искать.

## 2. Что именно это чинит

| Отказ, измеренный в текущей версии | Каким законом закрыт |
|---|---|
| Модель дописала запись в конец журнала вместо начала | 1 — порядок знает команда |
| Одно двоеточие в прозе валит разбор всего `NOW.md` | 3 — проза лежит в теле, разбор её не касается |
| 120 коммитов в неделю в один файл, параллельные ноги дерутся | 3 — каждый правит свой файл |
| Обязательное поле `started:` встречается **ноль раз** в обоих живых `NOW.md` | 1 — поле пишет команда, а не память агента |
| В шапках нарядов заведены самодельные ключи `exit_decided_2026_08_06`, `warning_2026_08_06` | 1 — команда принимает только известные поля |
| Две сессии в один день на одну задачу, 29 из 29 активных дней с несколькими сессиями | §5 слоты |
| Журнал не может сказать «эту ногу перебило вот этой» | §4 статус `superseded` |

## 3. Инструмент

Один вход: `python osctl.py <предмет> <действие> [--параметры]`.

```
osctl task close   --id t-house-2 --evidence history/2026-08-07-....md
osctl call issue   --id c-... --for t-house-6 --track сцена --to executor
osctl call status  --id c-... --set blocked --unblock-when "..."
osctl card set     --id t-house-2 --field status --value done
osctl card note    --id t-house-2 --block note --text "..."
osctl question add --text "..." --answer-by "перед копанием" --who владелец
osctl slot claim   --slot 2 --for c-...
osctl slot release --slot 2
osctl show         --id t-house-2
osctl find         --text "тоннель"
osctl check        --direction indie-game-development
```

Правила инструмента:

- **Известные поля только.** Неизвестное имя поля — отказ с перечислением известных.
  Самодельные ключи в шапке становятся невозможны.
- **Никогда не вставляет внутрь текста.** Только целое значение целого поля.
- **Пишет атомарно.** Записал во временный файл, перечитал, проверил, переименовал.
  Не прошло — исходный файл не тронут, и на выходе явная ошибка.
- **Ничего не оценивает.** Не решает, готово ли, правильно ли, достаточно ли.
  Это работа ИИ и владельца, а не скрипта.

**Журнал перестаёт быть рукописным файлом.** Тот отказ с записью в конец лечится
не аккуратностью, а тем, что писать туда руками больше некому: журнал —
это `git log` плюс поле в карточке, и порядок в нём не от кого зависеть.

## 4. Карточка

Один предмет — задача, наряд, узел, запись, вопрос, решение, ставка — один файл.

```markdown
---
id: t-house-2
kind: task
bet: g-1d84
track: дом
order: 5
status: open
---

## goal
Место, где груз не проходит просто так

## done_when
В доме есть хотя бы одно место, где груз не проходит просто так…

## description
Игроку надо решать: повернуть груз или зайти иначе.
```

- Между `---` только короткие поля: строка без переносов до 120 символов, число,
  булево, дата, пусто. Всё длинное — в тело блоком `## имя`.
- Тело — обычный markdown, читаемый глазами. Скрипт его не разбирает: он режет
  по строкам `## ` и заменяет блок целиком.
- Последняя строка — `END_OF_FILE: <путь>`. Обрезанный при передаче файл виден.

Формат уже доказан: конвертер раскладывает нынешний `NOW.md` на 48 карточек
и собирает обратно байт в байт (`panel/cards.py`, приёмка `verify.py 01a`).

**Терминальные статусы**, которых сегодня нет: `superseded` с обязательными
`superseded_by` и `at`. Без него нельзя записать, что одну ногу перебило другой —
дыра уже была залогирована во `FRICTION.md` 27 июля с пометкой «ждём второго случая»;
6 августа стало вторым.

## 5. Раскладка папок

```
live/<направление>/
  NOW.md            указатель: какая ставка, лимит полос, прогноз. ~30 строк, расти не может
  cards/            ЖИВОЕ — то, что сейчас в работе
  cards/closed/     ЗАКРЫТОЕ — тот же формат, та же команда читает
  history/2026-08/  отчёты по месяцам
  knowledge/
  work/
```

Живая папка не растёт: закрытая карточка переезжает в `closed/` командой,
а не остаётся числиться. Достать из закрытого просто — формат тот же,
`osctl show --id …` и `osctl find --text …` смотрят в обе папки.

Списков нет нигде. «Какие задачи в полосе дом» — это «все карточки с `track: дом`».
Списка никто не пишет, значит нечему разойтись.

## 6. Слоты

Ровно N рабочих копий с именами.

### Где лежит доска ключей

**Вне репозитория и вне всех рабочих деревьев.** Не в `.gitignore` внутри репо —
физически снаружи:

```
~/.osctl/slots/          Windows: C:\Users\<имя>\.osctl\slots\
                         macOS:   /Users/<имя>/.osctl/slots/
```

`pathlib.Path.home()` даёт этот путь одинаково на обеих системах. Переопределяется
переменной `OSCTL_STATE_DIR`, если понадобится.

Почему именно снаружи, а не гитигнором внутри — три причины, и каждая уже стоила:

- **Перезатирание.** В GasCoopGame доска лежала так, что её затирали. Файл внутри
  дерева живёт в чьём-то чекауте, а чекаутов девятнадцать.
- **`git reset --hard` и смена ветки** сносят или подменяют всё внутри дерева.
  Доска обязана пережить и то и другое.
- **Видимость.** Слепота 6 августа была именно в том, что состояние жило в ветке.
  Доска снаружи веток не знает вообще — её видят все копии одинаково.

Обратная сторона, и она честная: доска привязана к машине. Это правильно, потому
что рабочие копии тоже привязаны к машине.

### Как устроена, чтобы перезатирать было нечего

**Один слот — один файл.** Не общий `slots.json`, который два процесса пишут
одновременно и один затирает другого. Тот же третий закон, что и у карточек.

```
~/.osctl/slots/win-u2.lease
```

**Захват — атомарное создание файла.** `open(path, "x")` завершается ошибкой,
если файл уже есть. Это проверка-и-установка на уровне операционной системы:
двое не могут захватить один слот, даже если попали в одну миллисекунду.
Ни блокировок, ни библиотек, ни гонок. Работает одинаково на Windows и Mac.

**Освобождение — удаление файла.** Нечего затирать, потому что никто ничего
не переписывает: файл либо есть, либо нет.

В файле — подо что взят, кем, когда, из какой копии:

```yaml
for: c-exec-g-1d84-delivery-point-001
worktree: C:/my_global_workflow_worktrees/indie-slot-2
claimed: 2026-08-07 09:14
base: 8441787d
```

### Что это ловит

**Двойной захват слота** — атомарным созданием.

**Двойную работу над одним нарядом** — `osctl slot claim --for c-…` перед созданием
читает все четыре файла аренды и отказывает, если такой `for` уже занят. Четыре
крошечных файла, никакого разбора.

Именно это и есть разница с обычной арендой. Шестого августа между двумя ногами
было **5 часов 48 минут**: аренда вида «занято сейчас» к 13:51 была бы уже снята
и не помогла бы. А «этот наряд уже кем-то взят и не возвращён» не зависит от того,
сколько прошло времени.

**Забытую интеграцию** — слот нельзя освободить, не слив работу в `main`.
`osctl slot release` проверяет, что ветка слота — предок `origin/main`, и иначе
отказывает с двумя числами.

### Что осталось разобрать

Схему, уже работающую в GasCoopGame, я не прочитал — разведка оборвалась.
Перед реализацией её читают и берут оттуда то, что там доказано практикой;
изобретать заново нечего. Устройство выше — это то, что чинит названный
владельцем отказ с перезатиранием, а не замена тому разбору.

### Метка направления в рабочей копии

**Дыра, проверенная замером:** в `AGENTS.md` и `CLAUDE.md` ноль упоминаний
конкретного направления. Единственный сигнал сегодня — имя папки
(`…_worktrees/indie-game-development`), и он держится только на том, что папка
названа так же, как направление. Со слотами вида `slot-2` этот сигнал исчезает.
Плюс из любой копии видны ВСЕ направления в `live/`, и ничто не мешает сессии
взяться не за то.

Раскладка слотов — по направлениям, чтобы имя было видно и в пути тоже:

```
C:/workflow-slots/indie-game-development/slot-1/
C:/workflow-slots/indie-game-development/slot-2/
C:/workflow-slots/solmax/slot-1/
```

В корне каждой копии лежит неотслеживаемый файл:

```yaml
# .osctl-here.yaml
direction: indie-game-development
slot: 2
```

Читают его четверо, и это важно — метка полезна ровно настолько, насколько её
кто-то читает:

| Кто | Зачем |
|---|---|
| `osctl` | направление берётся отсюда, `--direction` становится не нужен |
| панель | показывает, какой слот подо что занят |
| сторож (расширение Pi, guard Codex, хук Claude) | разрешает запись только в `live/<direction>/**` — чужое направление физически недоступно из этого слота |
| сам агент | через одну строку в `AGENTS.md`: «направление — из `.osctl-here.yaml` в корне» |

Последняя строка — несущая. `AGENTS.md` отслеживается и читается всеми тремя CLI
автоматически; она и отправляет их к метке. Так мы не рассчитываем на то, что
новый файл кто-то подхватит сам.

### Что именно открывать агенту

**Корень слота, не папку направления.** Замерено на Pi 2026-08-07: если открыть
`live/indie-game-development/`, то `AGENTS.md` из корня репозитория загружается
(агент идёт вверх по папкам) и `../../os/` читается — правила не теряются.
Но проектный `.pi/` из корня НЕ подхватывается: Pi ушёл в чужого провайдера,
то есть потерялись и модель, и сторож. То же относится к `.codex/`
и `.claude/settings.json` — они привязаны к корню проекта, а корнем становится
открытая папка.

Корень слота — это корень рабочей копии, значит и корень проекта. Там есть всё:
правила, `os/`, конфиг инструмента, сторож. Направление берётся из метки.

**Отдельный репозиторий на направление рассмотрен и отвергнут.** Замерено:
направления почти не пересекаются (indie → solmax ноль ссылок; solmax → indie
одна в живом состоянии). Но правила `os/` общие, и при отдельных репозиториях их
пришлось бы копировать или тянуть подмодулем. Копии расходятся — а расхождение
и есть класс, который мы лечим; заводить его в сборнике правил хуже всего.
Слот как worktree делит объекты с репозиторием и стоит копейки; отдельные
репозитории умножают полную историю на число слотов.

**Дыра, остающаяся при любом варианте:** из любого слота видны все направления
в `live/`. Закрывается не правилом, а сторожем: в слоте indie запись разрешена
только в `live/indie-game-development/**`. Тот же механизм уже проверен — он
физически не дал Pi записать в `os/`.

**Нет метки — стоп, а не догадка.** Если копия сделана руками и файла нет,
`osctl` отказывается работать и говорит, что делать. Угадывать направление
по пути нельзя: неверная догадка хуже остановки — она пишет в чужое состояние.

Создаётся всё одной командой, чтобы метку не забывали:

```
osctl slot create --direction indie-game-development --slot 2
```
делает рабочую копию от `origin/main`, кладёт `.osctl-here.yaml`, добавляет его
в глобальный `core.excludesFile` — файл не отслеживается, переживает смену ветки
и никогда не пушится.

Слот принадлежит направлению постоянно: аренда меняется, метка нет.

## 7. Проверка и запасной выход

Три уровня, и ни один не судит содержание:

1. **Каждая запись проверяет себя.** Записал — перечитал — шапка разбирается,
   `id` совпадает с именем файла, хвост на месте. Нет — откат и явная ошибка.
2. **`osctl check`** — отдельный прогон по всему направлению. Сообщает только
   механические факты: что не разбирается, у чего нет хвоста, какая ссылка никуда
   не ведёт. Не «правильно ли», а «читается ли».
3. **Глаза.** Ассистент открывает получившийся файл и смотрит. Это не запасной
   вариант на крайний случай, а нормальный последний шаг: смысл судит ИИ и владелец,
   скрипт судит только байты.

## 8. Переносимость

Python 3 и стандартная библиотека плюс `PyYAML`. Ни PowerShell, ни `.cmd`,
ни `.sh` — вызов одинаков на Windows и на Mac:

```
python osctl.py task close --id t-house-2
```

Пути только через `pathlib`, файлы только в UTF-8 с явным указанием, переводы
строк не навязываются. Никаких вызовов оболочки внутри — кроме `git`,
который есть везде одинаково.

## 9. Чего сознательно не делаем

- **Никаких полей, которые агент пишет о себе** в духе «взято мной в 13:51».
  Такое поле уже есть — `started:` — и его соблюдаемость нулевая. Защита на
  честности агента это не защита.
- **Никаких скриптов-судей.** Проверка смысла, полноты и достаточности остаётся
  за ИИ и владельцем. Скрипт устанавливает только объективные факты.
- **Никакой базы данных как источника правды.** Markdown в git — единственный
  авторитет; всё остальное кэш, который можно снести и построить заново.
- **Ничего, что красное в покое.** Владелец пушит руками и забывает; сигнал,
  горящий каждый день, перестаёт быть сигналом.

## 10. Порядок

1. `osctl` с командами чтения и `check` — ничего не меняет, но уже видно состояние.
2. Формат карточки закрепляется, конвертер переводит живое направление.
3. Команды записи, по одной: сначала те, что закрывают задачу и меняют статус.
4. Слоты и уборка флота.
5. Панель показывает всё это; разделы идут по `panel/PLAN.md`.
