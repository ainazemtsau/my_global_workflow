## 3. ВХОД: что уже есть в `panel/cards.py`

Не пиши свой разбор карточек. Пользуйся готовым, и знай про него три вещи —

- `cards.build(direction)` — **стирает папку `panel/.cards/<direction>/` целиком**

- `cards.read_card(path)` возвращает **кортеж `(head, blocks)`**. `head` — словарь шапки.

  Текст поля получается `"\n".join(строки)` и больше ничем. `cards.body_value` НЕ применять.
- Любая ошибка чтения летит через `cards.fail`, который бросает **`SystemExit`**.
  `except Exception` его НЕ ловит. Ловить `except (Exception, SystemExit) as e`.

Ещё: `head` содержит поля типа `datetime.date` (`issued`), и `json.dumps` на них падает.
Отдавать JSON только так: `json.dumps(obj, ensure_ascii=False, default=str)`.

## 4. КОНТРАКТ

### 4.1 Новая ручка сервера

`GET /api/section/<direction-id>/now` → JSON.

**Когда пересобирать карточки.** Один раз при старте сервера, и потом только если
`live/<direction-id>/NOW.md` изменился позже, чем папка `panel/.cards/<direction-id>/`
(сравнение по времени изменения), или папки нет. На каждый запрос — НЕ пересобирать.
Пересборка и чтение папки одного направления происходят под одним общим
`threading.Lock`: сервер многопоточный, и без замка один поток сотрёт папку,
пока другой её читает.

```json
{
  "direction": "indie-game-development",
  "cards_total": 49,
  "ready": [ <наряд> ],
  "other": [ <наряд> ],
  "unread": [ {"file": "x.md", "error": "текст ошибки"} ]
}
```

`cards_total` — число файлов `.md` в папке карточек, включая нечитаемые.

Наряд — карточка `kind: call`. Другие виды в этот раздел не попадают.

**Форма наряда (значения ниже выдуманы, это образец формы, а не ожидаемый ответ):**

```json
{
  "id": "c-...",
  "status": "blocked",
  "track": "сцена",
  "for": "t-...",
  "title": "<текст goal задачи>",
  "title_source": "task",
  "why": "<текст unblock_when>",
  "fields": [ {"name": "note", "text": "..."} ],
  "head": { },
  "launch": "collect next for indie-game-development/сцена"
}
```

Правила, соблюдать буквально:

- `status`, `track`, `for`, `head` берутся из шапки карточки БЕЗ изменений.
  Нет `track` — в JSON `null`.
- **`ready`** — наряды, у которых `status` в шапке равен `ready`. **`other`** — все прочие.
  `len(ready) + len(other)` равно числу читаемых карточек `kind: call`.
  Наряд с незнакомым или отсутствующим статусом идёт в `other`, а не пропадает.
- **`title`** — текст поля `goal` карточки задачи, чей `id` равен `for` наряда.
  `goal` ищется сперва в шапке, потом среди блоков тела (тогда текст —
  `"\n".join(строк)`). Если задачи нет или `goal` у неё нет: `title` = `id` наряда,
  `title_source` = `"self"`. Иначе `title_source` = `"task"`.
- **`why`** — текст поля `unblock_when` наряда: из шапки, иначе из блока тела.
  Нет поля — `null`. Других источников нет, додумывать нечего.
- **`fields`** — ВСЕ блоки тела наряда, в исходном порядке, имена как есть,
  текст = `"\n".join(строк)` дословно. Ничего не отбирать, не сокращать,
  не переименовывать: в настоящих карточках есть поля `seam_added`,
  `warning_2026_08_06`, `exit_decided_2026_08_06`, и они обязаны дойти целиком.
- **`launch`** — ровно `collect next for <direction-id>/<track>`,
  а без `track` — `collect next for <direction-id>`.
- **`unread`** — карточки, чтение которых упало: имя файла и текст ошибки.
  Ошибка одной карточки не мешает остальным и не роняет запрос.
- Порядок: `ready` — по `track` (отсутствующий считается пустой строкой), затем по `id`.
  `other` — по статусу в порядке `running, waiting, blocked, paused`, всё незнакомое
  после них, внутри группы по `id`.
- Направление, которого нет в `live/`, или раздел не `now` → **404**, а не падение.
- Направление без карточек (`solmax`) → 200, пустые списки, `cards_total: 0`.

### 4.2 Что показывает страница

**Если `ready` не пуст** — каждый наряд строкой:
`<div class="row">` с `<div class="status">МОЖНО ЗАПУСКАТЬ · <track></div>`,
`<div class="title">` с `title`, затем по `<div class="desc">` на каждый элемент
`fields` (имя поля и текст), затем `<div class="id">` с `id`.

**Если `ready` пуст** — `<div class="empty">ЗАПУСКАТЬ НЕЧЕГО</div>`.

**На сегодняшних данных `ready` ПУСТ — все наряды заблокированы. Это верный
результат, а не твоя ошибка. Ничего не чини, чтобы он наполнился.**

**Ниже `other`**, каждый строкой: `<div class="status wait">` с текстом
`<СТАТУС ЗАГЛАВНЫМИ>` и, если `track` есть, ` · <track>`; `<div class="title dim">`
с `title`; `<div class="desc">` с `why`, если он не `null`; затем остальные `fields`;
затем `<div class="id">`.

**Если `unread` не пуст** — внизу `<div class="problem">` с текстом
`НЕ ПРОЧИТАЛОСЬ <N> — <имена файлов через запятую>`.

Только классы из `style.css`. Никаких инлайн-стилей, своих классов и цветов в JS.
Текст полей выводится дословно, без обрезания.

### 4.3 Что обязано сохраниться при переписывании

`serve.py` держит ровно эти маршруты, как сейчас:
`GET /` → `panel/app/index.html`; `GET /app.js` и `GET /style.css` → файлы
из `panel/app/` с правильным Content-Type; `GET /api/state` → как есть, включая
`build.commit`, `build.commit_date`, `build.unpushed`, `build.unread`,
список направлений из папок `live/` и семь разделов с `now: ready true`.
Флаги `--port` (по умолчанию 8787) и `--no-open`. Всё прочее — 404.

`app.js` сохраняет экран выбора, шапку, меню, хэш-роутинг и поведение неготовых
разделов дословно. Добавляется только отрисовка раздела `now`.
