# Этап 1a — конвертер NOW.md в карточки

## 1. GOAL

Скрипт, который читает `NOW.md` направления и раскладывает его на карточки — по файлу
на сущность — и умеет собрать их обратно, чтобы доказать, что не потеряно ничего.

Ничего в `live/` не пишется. Карточки складываются в `panel/.cards/<direction-id>/`.

## 2. СОЗДАТЬ (только новые файлы)

- `panel/cards.py` — не более 220 строк

Больше ничего не создавать и не менять.

## 3. ВХОД

`live/indie-game-development/NOW.md` и `live/solmax/NOW.md` — только на чтение.
Стандартная библиотека Python 3.13 плюс `yaml` (PyYAML 6.0.3 установлен).

Замеренная правда об этих файлах, на неё можно опираться:
indie даёт 1 ставку, 16 задач, 3 наряда, 27 записей, 1 решение — 48 карточек.
solmax даёт 0 карточек: у него `bet: none` (это СТРОКА, а не пусто), `issues` отсутствует,
остальные разделы — пустые списки.

## 4. КОНТРАКТ

### 4.1 Что чем становится

| Раздел `NOW.md` | Что получается | `kind` |
|---|---|---|
| `bet` | одна карточка, `id` = значение `bet["node"]` | `bet` |
| каждый элемент `tasks` | карточка | `task` |
| каждый элемент `open_calls` | карточка | `call` |
| каждый элемент `issues` | карточка | `issue` |
| каждый элемент `decisions` | карточка | `decision` |

`tracks`, `track_wip_limit`, `direction_forecast`, `recurring` карточками НЕ становятся.

Три правила про пустоту, соблюдать буквально:
- карточка ставки строится ТОЛЬКО если `bet` — словарь и в нём есть ключ `node`.
  Любое другое значение, включая строку `none`, карточки ставки не даёт и ошибкой не является;
- отсутствующий раздел и `null` считаются пустым списком — и при раскладке, и при сравнении;
- `build` всегда создаёт папку направления, даже если карточек ноль.

### 4.2 Одно правило раскладки, других нет

Для каждой пары ключ-значение исходной записи:

**В ШАПКУ** идёт значение, если оно: строка без переводов строки длиной ≤ 120 символов,
либо целое, либо дробное, либо булево, либо `None`, либо дата (`datetime.date`).

**В ТЕЛО** идёт всё остальное: длинная строка, многострочная строка, список, словарь.

Никаких исключений и никаких списков особых полей.

### 4.3 Форма файла карточки

Имя файла — `<id>.md`, папка — `panel/.cards/<direction-id>/`.

```markdown
---
id: t-house-2
kind: task
bet: g-1d84
pos: 5
track: дом
order: 5
status: open
---

## goal
Место, где груз не проходит просто так

## done_when
В доме есть хотя бы одно место, где груз не проходит просто так
и игроку надо решать — повернуть груз или зайти иначе.

END_OF_FILE: panel/.cards/indie-game-development/t-house-2.md
```

**Шапка.** Строится словарём в таком порядке ключей: `id`, `kind`, `bet` (если есть),
`pos`, затем поля исходной записи в их исходном порядке. Печатается РОВНО так:

```python
yaml.safe_dump(head, sort_keys=False, allow_unicode=True, default_flow_style=False)
```

Вручную строки шапки не форматировать: реальные значения содержат `": "` и без
`safe_dump` шапка перестаёт разбираться.

**Служебные поля шапки:**
- `kind` — вид карточки;
- `pos` — номер записи в её исходном списке, с нуля. У карточки ставки `pos: 0`;
- `bet` — значение `NOW["bet"]["node"]`, добавляется карточкам `task`, `call`, `decision`.
  Если ставки нет — поле не добавляется. Если у исходной записи УЖЕ есть ключ `bet` —
  падать с явной ошибкой, ничего не перезаписывая.

**Тело.** Пустая строка после закрывающего `---`, затем блоки подряд. Блок:

```
## <имя поля>
<значение ровно как есть, байт в байт>
```

и сразу за значением ровно один перевод строки, после которого начинается следующий
`## ` или строка `END_OF_FILE:`. Если само значение оканчивалось переводом строки,
перед следующим блоком получится пустая строка — так и должно быть, это и есть
способ отличить `"текст\n"` от `"текст"`.

Порядок блоков — исходный порядок ключей.

Если значение содержит строку, начинающуюся с `## `, — падать с явной ошибкой.
(Проверено: в сегодняшних данных таких нет.)

**Хвост.** Последняя строка файла:
`END_OF_FILE: panel/.cards/<direction-id>/<id>.md`

### 4.4 Что умеет скрипт

```
python panel/cards.py build <direction-id>
```
Читает `live/<direction-id>/NOW.md`, полностью очищает и заново создаёт
`panel/.cards/<direction-id>/`, пишет карточки. В конце печатает строку вида
`построено <всего> карточек: bet <n>, task <n>, call <n>, issue <n>, decision <n>` —
все пять видов печатаются всегда, включая нули. Числа в этом примере — это ФОРМАТ,
а не ожидаемый ответ.

```
python panel/cards.py check <direction-id>
```
Читает карточки с диска, собирает из них обратно структуру и сравнивает с тем,
что даёт `yaml.safe_load` файла `live/<direction-id>/NOW.md` — по разделам
`bet`, `tasks`, `open_calls`, `issues`, `decisions`. Сравнение по данным, не по байтам.

Списки восстанавливаются в порядке `pos`.

**Что отбрасывается при обратной сборке** — и ничего кроме:
`kind`, `pos`, `bet` (только если он был добавлен служебно), строка `END_OF_FILE`.
У карточки `kind: bet` отбрасывается ТАКЖЕ `id` — в исходнике его не было,
его значение живёт там как `node`.

Печатает `СОВПАДАЕТ` и возвращает 0, либо печатает путь до первого расхождения
и оба значения (обрезав до 200 символов) и возвращает 1.

`check` ОБЯЗАН каждый раз читать `live/<direction-id>/NOW.md` заново с диска.
Сравнивать карточки с тем, что осталось в памяти от `build`, — проваленная задача.

## 5. ЧТО РАЗРЕШЕНО

`yaml.safe_load`, `yaml.safe_dump`, `os`, `sys`, `shutil`, `argparse`, `datetime`.

Шапка карточки разбирается ТОЛЬКО `yaml.safe_load` куска между первой и второй
строкой `---`. Тело режется по строкам, начинающимся с `## `. Больше никаких
регулярных выражений по содержимому, никакой починки на лету, никаких догадок.
Не разбирается — падай с явным текстом ошибки.

НЕ писать ничего в `live/`, `os/`, `archive/`.
