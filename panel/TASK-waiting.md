# Наряд: раздел «ЖДЁТ ТЕБЯ»

Ты дописываешь панель направлений в этом репозитории. Писать можно только в
`panel/**` — сторож остальное не пропустит, и это правильно.

## Что делаем

Раздел `waiting` («ЖДЁТ ТЕБЯ») сейчас заглушка. Надо его построить.

**Смысл раздела, и он единственный:** сюда попадает только то, где **отвечает
владелец**. Не «важное», не «срочное», не «список дел» — именно то, где ждут
ЕГО слова. Всё, что адресовано плею или ждёт события, сюда не идёт.

## Данные: что показывать

Читай карточки через уже существующий `serve.load_cards(direction)` — он
возвращает `{id: (head, blocks)}` и кладёт в шапку служебный `_closed`.

Пять источников, в этом порядке:

| Группа | Условие отбора | Заголовок группы |
|---|---|---|
| 1 | `_kind == "decision"`, не закрыта | `РЕШЕНИЕ` |
| 2 | `_kind == "question"`, не закрыта | `ВОПРОС` |
| 3 | `_kind == "call"`, не закрыта, `to == "owner"` | `НАРЯД К ТЕБЕ` |
| 4 | `_kind == "call"`, не закрыта, `status` из `blocked`/`waiting`/`paused` | `СТОИТ` |
| 5 | `_kind == "node"`, не закрыта, пустой `label` | `ЦЕЛЬ БЕЗ ИМЕНИ` |
| 6 | `_closed` истинно, `_kind` из `task`/`node`, `status` НЕ `done` и НЕ `dropped` | `ЗАКРЫТО БЕЗ ПРИЧИНЫ` |

Группы 1–4 — «работа стоит», они идут первыми. Группы 5–6 — «нужно твоё слово,
но ничего не стоит», идут после. Внутри группы — по `id`.

**Записи (`_kind == "issue"`) НЕ ПОКАЗЫВАЕМ.** У них свой отвечающий (поле
`route`) и условие событием, а не датой — вычислить «пора» нельзя, и показывать
их значило бы врать. Вместо этого одна строка внизу: сколько их всего.

## Данные: что класть в каждую строку

Для любой карточки:

- `id`
- `kind` — значение `_kind`
- `group` — ключ группы из таблицы выше (`decision`, `question`, `owner_call`,
  `stalled`, `unnamed_goal`, `closed_unnamed`)
- `blocking` — булево: `true` для групп 1–4, `false` для 5–6
- `title` — первое непустое из: `label`, `q`, `question`, `goal`, `description`,
  затем блок тела с тем же именем, затем `id`
- `detail` — блок тела `options` или `recommendation` или `why`, если есть, иначе `null`
- `since` — `opened` или `issued` из шапки, если есть, иначе `null`

Длинные значения могут лежать И в шапке, И блоком тела. Бери из шапки, если там
строка; иначе через `block_text(blocks, name)`. Блок под меткой ```yaml
разбирай через `cards.body_value(path, name, lines)` — он вернёт список или словарь.

## Выдача ручки `/api/section/<направление>/waiting`

```json
{
  "direction": "indie-game-development",
  "blocking": [ ...строки групп 1-4... ],
  "other":    [ ...строки групп 5-6... ],
  "issues_parked": 32,
  "unread": [ {"file": "...", "error": "..."} ]
}
```

`unread` — второй элемент из `load_cards`, отдать как есть.

## Вид

Функция `renderWaiting(direction, content)` в `panel/app/app.js`, вызывать из
диспетчера рядом с `renderDashboard`/`renderSlots`/`renderWave`/`renderGoals`.

Используй ТОЛЬКО существующие классы из `panel/app/style.css`: `row`, `status`,
`status wait`, `title`, `title dim`, `desc`, `human`, `id`, `empty`, `numbers`,
`num`, `problem`, `group`, `sec-title`. Своих классов и инлайн-стилей не заводи —
их наличие валит приёмку `verify 00`.

Строка — как в других разделах: сверху `div.status` со словом группы, ниже
`div.title` с текстом, ниже `div.desc` с подробностью, внизу `div.id` с id.
Для неблокирующих используй `status wait` и `title dim`.

Числа сверху через существующий рисовальщик строк-чисел или свой `div.numbers`
с `span.num`: «ждёт ответа N» и «нужно имя N» — только те, что больше нуля.

Внизу одной строкой `div.desc`: «N записей ждут своего события, дат у них нет».

Пусто во всех группах — `div.empty` с текстом `НИЧЕГО НЕ ЖДЁТ`.

Текст, приходящий с сервера, вставляй через `textContent` либо через
`window.mdToHtml` — прямой `innerHTML` запрещён и ловится приёмкой.

## Включить раздел

В `panel/serve.py` добавь `"waiting"` в `READY_SECTIONS` — на своё место,
порядок кортежа должен совпасть с порядком в `SECTIONS`: `slots`, `waiting`,
`wave`, `goals`.

В `panel/verify.py` в шаге 00 есть проверка списка готовых разделов — поправь
ожидаемый список там же.

## Чего делать НЕЛЬЗЯ

- писать куда-либо кроме `panel/**`;
- трогать `live/**`, `os/**`, любые карточки, любые git-команды;
- заводить новые виды карточек, новые поля или новые статусы;
- показывать `issue` в списках;
- угадывать «пора/не пора» — если в данных нет ответа, показывать нечего.

## Как проверить, что готово

Прогони по очереди и покажи вывод:

```
python panel/verify.py
python panel/test_readers.py
python panel/test_carrier.py
```

Все три обязаны сказать `ПРИНЯТО`. `verify` поднимает свой сервер на 8787 —
если порт занят, он честно откажется; тогда просто скажи об этом, ничего не убивая.

Отдельно покажи ответ ручки:

```
python -c "import json,subprocess,sys,time,urllib.request; p=subprocess.Popen([sys.executable,'panel/serve.py','--port','8796','--no-open']); time.sleep(3); print(json.dumps(json.loads(urllib.request.urlopen('http://127.0.0.1:8796/api/section/indie-game-development/waiting',timeout=20).read().decode()),ensure_ascii=False,indent=1)[:1200]); p.terminate()"
```

Сегодня в данных: **1 решение** и **9 целей без имени у solmax**, у инди целей
без имени нет. Если получилось иначе — не подгоняй, а скажи, что вышло.
