# Наряд: раздел «ИДЕИ»

Ты дописываешь панель направлений в этом репозитории. Писать можно только в
`panel/**` — сторож остальное не пропустит, и это правильно.

## Что делаем

Раздел `ideas` («ИДЕИ») ещё не существует. Надо его построить.

**Смысл раздела, и он единственный:** здесь лежит отложенное СОДЕРЖАНИЕ — то,
что придумали, но строить никто не обязался. Идея НИКОГДА не требование. Раздел
ничего не оценивает, не сортирует по важности и не советует, за что взяться.

Главное свойство строки — **видно, чья это идея**. Слова владельца и выдумка
ноги не имеют права выглядеть одинаково. Если авторство не записано — так и
показываем, НЕ угадываем.

## Что уже есть и что трогать нельзя

- `serve.load_cards(direction)` возвращает `{id: (head, blocks)}` и кладёт в
  шапку служебный `_closed`. Пользуйся им, своего разбора не пиши.
- `serve.SECTIONS` — список разделов, `serve.READY_SECTIONS` — какие открыты.
- Маршрут `/api/section/<направление>/<раздел>` в `Handler.route`.
- Отрисовка разделов в `panel/app/app.js`, вид — только классами из
  `panel/app/style.css`. **Ни одного цвета в JS, ни одного инлайн-стиля.**
- `live/**`, `os/**`, `osctl.py` не трогаешь вообще.

## Что сделать, по шагам

### 1. Раздел появляется в меню

В `serve.SECTIONS` добавь `("ideas", "ИДЕИ")` **между `goals` и `history`**.
В `serve.READY_SECTIONS` добавь `"ideas"`.

### 2. Чистая функция строки — `serve.idea_row(cid, head, blocks)`

Возвращает словарь ровно с этими ключами:

| Ключ | Откуда | Если нет |
|---|---|---|
| `id` | `cid` | — |
| `text` | блок `idea`, строки склеены переводом строки | `None` |
| `his_words` | блок `his_words` | `None` |
| `from` | поле шапки `from` | `None` — **не подставляй ничего** |
| `about` | поле шапки `about` | `None` |
| `source` | поле шапки `source` | `None` |
| `opened` | поле шапки `opened`, строкой | `None` |

Пустой блок (есть, но в нём одни пустые строки) считается отсутствующим.

Функция чистая: ничего не читает с диска, ничего не печатает.

### 3. Раздел — `serve.section_ideas(direction)`

Берёт живые карточки (`_closed` ложно) с `_kind == "idea"`, делает строки
функцией из шага 2 и группирует по `about`:

- группа на каждое значение `about`, у которого есть живая карточка-цель:
  заголовок — `label` этой цели, а если имени нет — её `id`;
- всё, у чего `about` пусто ИЛИ указывает на несуществующую карточку, —
  в последнюю группу с заголовком `про направление целиком`;
- внутри группы строки по `id`.

Возвращает:
```
{"direction": <строка>, "count": <всего строк>, "groups": [
    {"about": <id или null>, "label": <заголовок>, "rows": [<строки>]}]}
```

Группы с целью идут первыми по `label`, «про направление целиком» — последней.
Пустых групп не бывает.

### 4. Маршрут

`/api/section/<направление>/ideas` отдаёт результат шага 3. Делай ровно как
сделаны `wave` и `goals` — тем же способом, в том же месте.

### 5. Отрисовка в `app.js`

Функция `renderIdeas(direction, content)` по образцу `renderWave`.

- Заголовок группы — как в других разделах.
- Строка: сначала текст идеи, под ним — служебная подпись из того, что есть:
  автор, дата, ссылка на источник. Всё машинное (id, дата, путь) —
  моноширинным классом, человеческое — обычным.
- Если у строки есть `his_words` — показать их отдельно и заметно: это цитата
  владельца, а не пересказ.
- Если `from` пусто — вывести подпись `автор не записан` тем же тусклым
  классом, каким показывается ждущее.

**Тексты для владельца — дословно, не переписывай и не переводи:**

- когда `count == 0`, вместо списка одна строка:
  `Пока ни одной. Захват ног живёт в отчётах — перенос оттуда отдельная работа.`
- подпись под заголовком раздела, всегда:
  `Отложенное содержание. Ничего из этого не является требованием.`
- подпись автора: `его слова` при `from: владелец`, `придумала нога` при
  `from: нога`, `автор не записан` при пустом.

### 6. Стиль

Нужные классы, скорее всего, уже есть в `style.css`. Если чего-то не хватает —
добавь в `style.css`, а не в разметку. Новых цветов не заводи: бери
существующие переменные.

## Приёмка

Гоняй, пока обе не станут зелёными:

```
python panel/test_readers.py
python panel/verify.py
```

`test_readers` проверяет шаг 2 напрямую, `verify` — шаги 1 и 4.
Эталоны написаны ДО этого наряда и не мной — не подгоняй их под свой код.
Если приёмка кажется неправильной — **останавливайся и говори**, а не
обходи её.

## Чего делать нельзя

- Не оценивать идеи, не считать «важность», не сортировать по чему-либо,
  кроме указанного.
- Не выдумывать автора, дату и источник, если их нет в карточке.
- Не писать в `live/**`, `os/**`, `osctl.py`.
- Не менять `panel/verify.py` и `panel/test_readers.py`.
- Не сочинять обращённый к владельцу русский текст: он выше, дословно.
