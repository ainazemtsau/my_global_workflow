# Workflow 2.0 — цель, решения, этапы

Этот файл — точка входа. Новый чат начинает с него и с `.pi/README.md`.
Владелец: Антон. Ведёт разговор Claude Code, код пишет Pi, проверяет Codex.

## Цель

Владелец открывает панель двойным кликом и ведёт по ней всю работу над направлениями,
**не открывая ни одного markdown-файла**. Формат хранения при этом переделан так, что
каждый файл читается машиной целиком и всегда.

Две половины, и обе обязательны. Только панель — это витрина над сломанным хранилищем.
Только формат — это работа, которой владелец не видит.

## Как поймём, что дошли

1. Все семь разделов работают для обоих направлений.
2. Красная полоса «не прочиталось» пуста: ни один файл состояния не падает при разборе.
3. Владелец за неделю ни разу не открыл markdown, чтобы понять, что происходит.
4. Направление может добавить свой раздел, не трогая код панели.

## Что уже решено, и почему

| Решение | Почему |
|---|---|
| Приложение с разделами, не одна страница | владелец заходит в направление и ходит по разделам; адрес меняется, можно кинуть ссылку |
| Локальный сервер, разбор файлов на лету | статический html не может читать файлы из браузера; база — второй источник правды, который разойдётся. Данных мало, разбор занимает доли секунды |
| Без фреймворка (React и подобные) | сборка, npm-зависимости и конфиги — места, где Pi ломается; переключение разделов это ~40 строк. Пересмотрим, если внутри панели появится сложное редактирование |
| Тёмная тема основная | слово владельца |
| У каждого файла состояния — шапка машинных полей, тело по типу | мысль владельца: панель показывает списки, не заглядывая внутрь. Шапка это 4–6 строк |
| `history/`: шапка только НОВЫМ отчётам | 263 старых — неизменяемые записи о том, что было; переписывать историю задним числом нельзя. Для них метаданные из имени файла и git |
| `LOG.md` убираем как источник, историю берём из git | три направления — три несовместимые грамматики (indie 32/32, solmax 0/109); git единообразен по построению |
| `CHARTER.md`: тело остаётся прозой | там миссия, ограничения, премортем — типизировать нечего, попытка сделает хуже |
| Настройки панели живут в `panel/`, не в `live/` | `live/` — состояние направления; настройки внешнего вида там разойдутся |
| Панель ничего не оценивает и не советует | посчитанная сложность или готовность — выдумка; данных для них в файлах нет |
| Файл прочитан, только если `yaml.safe_load` дал словарь И последняя непустая строка — его `END_OF_FILE:` | замерено: обрезанный на 90% `NOW.md` читается начисто и молча показывает 1 наряд вместо 3 |
| Не прочиталось — показываем сырым текстом под красной полосой, с точным текстом ошибки | молчаливая подмена хуже пустого места |
| Pi создаёт файлы целиком, а не правит строки | его инструмент правки ошибается в 3–6% вызовов, и был баг с переписыванием всего файла в нормализованном виде |
| Эталоны для проверки пишет не та модель, что пишет код | иначе она проверяет сама себя |
| Дефолт работает из коробки, кастомизация — сверху, никогда «вместо» | слово владельца |
| `life-reset` убран в `archive/live-life-reset` (коммит `af9c8c16`) | направление закрыто; в архиве ссылки из истории solmax не рвутся |
| Каждый этап обсуждается ДО работы и записывается сюда | владелец должен иметь возможность проверить решение через месяц |

## Чем меряем, подходит ли формат файла

Формат остаётся как есть, только если проходит все пять:

1. Машина читает файл целиком и всегда, одним обычным парсером.
2. У каждой сущности стабильный id.
3. Проза не может сломать разбор.
4. Параллельные ноги не дерутся за один файл.
5. Видно, если файл обрезался при передаче.

Вердикты по замерам 2026-08-06: `NOW.md` — переделываем (проза валит весь файл, 120 коммитов
в неделю в один файл). `TREE.md` — переделываем (уже сломан: строка 3 на 20 533 символа).
`CHARTER.md`, `history/`, `knowledge/` — тело оставляем, шапку добавляем. `LOG.md` — убираем.

## Стиль

Слово владельца 2026-08-06: «брутальный минимализм, который отлично смотрится на OLED,
глубокий чёрный, минимально, но со своим вкусом». Делается под него лично, не «для всех».
Панель может позже уйти в open source, поэтому стиль закладывается сразу и живёт одним
файлом `panel/app/style.css` — чтобы его можно было заменить целиком, не трогая разметку.

| Решение | Почему |
|---|---|
| Фон — чистый `#000000` | на OLED пиксель выключается физически; это и есть та глубина, ради которой всё затевается |
| Структуру держат волосяные линии `#1c1c1c` и пустота, а не серые плашки | любая заливка на OLED светится и съедает глубину |
| Цвет только как сигнал, никогда как украшение | цветное пятно в блоке ровно одно — статус |
| Статус — строка заглавными моноширинным, в цвете | не бледный ярлычок; видно боковым зрением |
| Машинное моноширинным, человеческое обычным шрифтом | id, хеши и даты сразу отличаются от смысла |
| Ждущее гаснет: заголовок серее, чем у готового | взгляд сам идёт туда, куда надо |
| Проблема — красной полосой внизу экрана | не всплывашка и не иконка: есть — видно, нет — её нет |
| Текст не чисто белый, `#f0f0f0` / `#7d7d7d` / `#3d3d3d` | чистый белый на чёрном режет глаз |

Сигнальные цвета: янтарь `#ffb224` — ждёт; красный `#ff4438` — сломалось.
Акцент (готово к запуску, активный раздел) — **кислотный лайм `#c8ff33`**, вариант А,
выбран владельцем 2026-08-06. Максимальный контраст на чёрном, не расплывается как циан
и не сливается с янтарём как оранжевый.

Стиль живёт целиком в `panel/app/style.css`. Разметка использует только его классы:
ни инлайн-стилей, ни цветов в JS. `verify.py` следит, что акцент и фон не перекрашены.

### Уроки, которые дорого дались

- **Читатель переживает свой источник.** Трижды подряд: мир менялся, код
  оставался и получал ПУСТОТУ вместо ошибки. Сторож — `panel/test_readers.py`,
  он проверяет согласие кода с моделью, а не поведение.
- **И читатель этот не обязательно код.** Сам этот файл двое суток описывал
  позавчерашний мир: коммит, который назывался «точка входа стала точной»,
  оставил ниже раздел с «переезд ещё нельзя». Свежий чат прочитал его сверху
  вниз и начал не с того места. Сторож — `panel/test_docs.py`.
- **Приёмка, строящая себе мир, слепа.** Фикстура сама создавала `LOG.md` и
  потому не видела, что его удалили. Форма приёмки обязана быть формой жизни.
- **Панель не решает за владельца.** «Сделано» только от статуса `done`;
  закрытое без причины — «ЗАКРЫТО», а не «сделано»; стоящий наряд показывает
  своё условие, а не объявляется ждущим владельца.
- **Одно поле — один источник.** Накладка имён `os2/labels/` жила рядом с
  карточками, панель читала её и игнорировала карточку.
- **Проза с двоеточием — проза.** `yaml.safe_load` на значении шапки
  превращал предложение владельца в отображение.
- **Сигнал, который горит в покое, — не сигнал.** Приёмка держала фиксированный
  порт 8787 и краснела строкой «порт занят» каждый раз, когда владелец просто
  пользовался панелью. Это не дефект, а работа инструмента; красная строка про
  неё приучает не смотреть на красное. Порт теперь берётся у системы.

## Как работаем

| Кто | Что делает |
|---|---|
| Владелец | решает, смотрит результат, говорит «да» или «не так» |
| Claude Code | ведёт разговор, пишет карточку задачи, фикстуры и эталоны, коммитит |
| Pi, `qwen3.8-max-preview` | пишет код по карточке, гоняет проверку |
| Codex | отдельной свежей сессией пытается опровергнуть, что этап сделан |

Карточка задачи для Pi лежит в `panel/` и называется по разделу, который строит
(`panel/TASK-waiting.md` — последняя). Запуск (сторож обязателен, подробности
в `.pi/README.md`):
```
pi -a -e .pi/extensions/guard.ts -p "$(cat panel/TASK-waiting.md)"
```

Каждый этап проверяется дважды: приёмки считают конкретные числа и падают,
если не сошлись; владелец открывает страницу и говорит, стало лучше.

### Что значит «аккуратно» в текущей ветке

Работа панели живёт в текущей ветке рядом с состоянием направлений. Четыре условия,
которые делают это безопасным:

1. Работа идёт в рабочей копии `wt/indie-game-development`, оттуда же поднята панель;
   ветка отправляется в `main`. Корневая копия репозитория отстаёт — начинать с неё
   значит читать позавчерашнее состояние.
2. Каждый коммит перестройки начинается с `panel:`, `osctl:` или `workflow2:` —
   отличим с одного взгляда, при нужде откатывается по префиксу. Раньше перестройка
   не трогала `live/` и `os/` вовсе; после волн 3 и 4 это неправда, поэтому граница
   держится не папкой, а тем, что состояние меняется только командами `osctl`.
3. Сторож физически не даёт Pi писать вне разрешённых папок, так что даже ошибочная
   задача не заденет состояние направления.
4. В этой ветке параллельно работают другие сессии. Перед коммитом всегда проверять
   `git status` и добавлять только свои пути — никогда `git add -A`.
