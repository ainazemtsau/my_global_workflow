## Что сделать, по шагам

### 1. Раздел появляется как готовый

В `serve.READY_SECTIONS` добавь `"history"`. В `serve.SECTIONS` он уже есть,
трогать список не надо.

### 2. Чистая функция `serve.leg_from_name(fname)`

Из имени файла отчёта делает `{"date": "2026-08-09", "leg": "s-work-…-001"}`.

- Имя ноги — всё между датой и `.md`.
- Если имя не начинается с `ГГГГ-ММ-ДД-` — возвращай `None`. Это не нога:
  так в папке лежит `LOG-archive-<направление>.md`, архив прежнего общего
  журнала. Он не строка списка.
- Функция чистая: ничего не читает с диска.

### 3. Чистая функция `serve.history_row(fname, play, commit)`

`commit` — либо `None`, либо `{"sha", "date", "subject"}`. Возвращает:

| Ключ | Откуда | Если нет |
|---|---|---|
| `date`, `leg` | из шага 2 | — |
| `play` | аргумент `play` | `None` — **не подставляй ничего** |
| `text` | `commit["subject"]` | `None` |
| `sha` | `commit["sha"]` | `None` |
| `path` | `live/<направление>/history/<fname>` | — |

Направление бери из аргумента или замыкания — как удобнее, но путь должен быть
настоящим, от корня репозитория, через `/`.

Функция чистая.

### 4. Раздел — `serve.section_history(direction)`

1. Перебери `live/<направление>/history/*.md`, отбрось те, где шаг 2 дал `None`.
2. Для каждого отчёта достань `play:` — первое совпадение `^play:\s*(\S+)` в
   первых ~700 байтах файла. Нет — `None`.
3. Один вызов `git log` на весь раздел (не по файлу на вызов!):
   `git log --diff-filter=A --name-only --pretty=format:...` по пути
   `live/<направление>/history`. Разбери в `{имя файла: {sha, date, subject}}`.
   Если один файл добавлен несколькими коммитами — бери первый встреченный
   (`git log` идёт от новых к старым).
4. Собери строки шагом 3, сгруппируй по `date`, **дни новыми сверху**, внутри
   дня — по `leg`.

Возвращает:
```
{"direction": <строка>,
 "days": [{"date": "2026-08-09", "rows": [<строки>]}],
 "count": <всего ног>,
 "without_commit": <сколько строк без сообщения>,
 "without_play": <сколько строк без плея>,
 "archive": <путь к LOG-archive-*.md или null>}
```

`without_commit` и `without_play` — обязательные числа, даже когда они нули.
Раздел, который молча показывает меньше, чем есть, — это тот отказ, ради
которого написан `panel/test_readers.py`.

**Кэш не заводи.** Вызов `git log` занимает около секунды на 222 отчётах —
это приемлемо, а кэш стал бы вторым источником правды, который однажды
разойдётся с первым.

### 5. Маршрут

`/api/section/<направление>/history` отдаёт результат шага 4 — ровно тем же
способом, что `ideas` и `goals`.

### 6. Отрисовка в `app.js`

Функция `renderHistory(direction, content)`.

- Заголовок группы — дата, как заголовки групп в других разделах.
- Строка ноги: сообщение коммита обычным шрифтом (это человеческий текст),
  под ним служебная подпись моноширинным: плей, id ноги, короткий хеш, путь
  к отчёту.
- Плея нет — вместо него `плей не записан`, тусклым классом.
- Сообщения нет — вместо него `коммит не найден`, тусклым классом.
- Внизу раздела, всегда одной строкой — числа из шага 4.

**Тексты для владельца — дословно, не переписывай:**

- подпись под заголовком раздела:
  `Что делали ноги, по дням. Строка — сообщение коммита, которым нога закончилась.`
- строка чисел внизу:
  `Всего ног: N. Без сообщения: X. Без плея: Y.`
  (подставь числа вместо N, X, Y)
- ссылка на архив, когда `archive` не пуст:
  `Прежний общий журнал направления лежит архивом:` и следом путь.
- когда `count == 0`: `Пока ни одной ноги.`
