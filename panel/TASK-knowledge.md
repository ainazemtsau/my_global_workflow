# Наряд: раздел «ЗНАНИЯ»

Ты дописываешь панель направлений в этом репозитории. Писать можно только в
`panel/**` — сторож остальное не пропустит, и это правильно.

## Что делаем

Раздел `knowledge` («ЗНАНИЯ») сейчас закрыт. Надо его построить.

**Смысл раздела:** принятые факты направления — то, обо что ноги обязаны
проверять свою работу. Владелец открывает его, чтобы увидеть, что мы уже
считаем решённым, и кто это читает.

## Данные

Файлы `live/<направление>/knowledge/*.md`. Замерено 2026-08-09 на 15 записях
обоих направлений — числа приведены, чтобы ты не строил на том, чего нет:

| Что | Как выглядит | Насколько полно |
|---|---|---|
| заголовок | первая строка файла, `# Текст` | 15 из 15 |
| `accepted:` | дата и кем принято, одной строкой | 15 из 15 |
| `status:` | обычно `current` | 14 из 15 |
| кто читает | **`read_by:` ИЛИ `reads:`** — два имени одного поля | 13 + 2 = 15 из 15 |
| `source:` | указатель на отчёт/артефакт | 10 из 15 |

**Имён у поля «кто читает» действительно два**, и знать надо оба: `read_by`
стоит в тринадцати записях, `reads` — в двух, читателя нет ни у одной.
Прочитать только одно значило бы объявить читателя неназванным там, где он
назван. (Числа исправлены после наряда: первый замер читал лишь первые 1200
байт файла и насчитал 8 — поля ниже длинного `fact:` в окно не попали.)

**Устаревание НЕ вычисляем.** `status: current` стоит у всех четырнадцати, у
кого статус вообще есть; вывести из этого «протухло» неоткуда. Показывай
`accepted` и `status` как есть — судят их владелец и плеи `review`/`pulse`.

## Что сделать, по шагам

### 1. Раздел появляется как готовый

В `serve.READY_SECTIONS` добавь `"knowledge"`. В `serve.SECTIONS` он уже есть.

### 2. Чистая функция `serve.knowledge_row(fname, text)`

Разбирает ТЕКСТ файла (шапка — строки до первого `## `). Возвращает:

| Ключ | Откуда | Если нет |
|---|---|---|
| `id` | имя файла без `.md` | — |
| `title` | первая строка вида `# Текст`, без решётки | имя файла |
| `accepted` | значение `accepted:` | `None` |
| `status` | значение `status:` | `None` |
| `reader` | значение `read_by:` **или** `reads:` | `None` |
| `source` | значение `source:` | `None` |
| `body` | всё, начиная с первой строки `## ` | `""` |
| `path` | `live/<направление>/knowledge/<fname>` | — |

Значение поля — весь остаток строки и её продолжения (в записях `reads:`
занимает две строки). Пустое значение — это `None`, а не пустая строка.

Функция чистая: ничего не читает с диска и ничего не печатает.

### 3. Раздел — `serve.section_knowledge(direction)`

Читает папку, делает строки шагом 2, сортирует по `accepted` — **новые
сверху**; записи без даты идут последними, между собой по `id`.

Возвращает:
```
{"direction": <строка>, "count": <всего>,
 "without_reader": <сколько без читателя>,
 "without_status": <сколько без статуса>,
 "rows": [<строки>]}
```

Числа обязательны, даже когда нули.

### 4. Маршрут

`/api/section/<направление>/knowledge` — ровно тем же способом, что `history`.

### 5. Отрисовка в `app.js`

Функция `renderKnowledge(direction, content)`.

- Строка: заголовок записи человеческим шрифтом; под ним служебная подпись
  моноширинным — дата принятия, статус, источник.
- Кто читает — отдельной строкой, человеческим шрифтом: это самое полезное
  в записи.
- Тело показывается по кнопке `подробности`, как уже сделано в «Сейчас»
  (`details` + `el("button", "act", "подробности")` + `mdNode`) — тем же
  приёмом, не изобретай второй.
- Нет читателя — вместо него `читатель не назван`, тусклым классом.
- Нет статуса — `статус не проставлен`, тем же тусклым классом.

**Тексты для владельца — дословно, не переписывай:**

- подпись под заголовком раздела:
  `Принятые факты. Кто их читает — из самой записи; устаревание никто не вычисляет.`
- строка чисел внизу:
  `Всего записей: N. Без читателя: X. Без статуса: Y.`
- когда `count == 0`: `Пока ни одной записи.`
- вместо пустого читателя: `читатель не назван`
- вместо пустого статуса: `статус не проставлен`

### 6. Стиль

Классы бери существующие. Новых цветов не заводи. Не хватает класса — добавляй
в `style.css`, не в разметку.

## Приёмка

```
python panel/test_readers.py
python panel/verify.py
```

Обе написаны ДО этого наряда и не мной. Не подгоняй их под свой код. Если
приёмка кажется неправильной — **останавливайся и говори**, а не обходи.

## Чего делать нельзя

- Не вычислять устаревание и не рисовать «протухло».
- Не оценивать записи и не сортировать по важности.
- Не выдумывать читателя, статус и источник, если их нет.
- Не писать в `live/**`, `os/**`, `osctl.py`.
- Не менять `panel/verify.py` и `panel/test_readers.py`.
- Не сочинять обращённый к владельцу русский текст: он выше, дословно.
