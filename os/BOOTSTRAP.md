# BOOTSTRAP — запуск направления

Пакеты писать руками не нужно: вход — обычные слова. CALL/RESULT являются машинным транспортом.

## Вариант A: ChatGPT / Claude Project

1. Создай Project с именем направления.
2. Скопируй блок из `os/adapters/SESSION_PAYLOAD.md`, замени `<direction-id>`.
3. Дай проекту read-доступ к `ainazemtsau/my_global_workflow`. Без коннектора загрузи `os/KERNEL.md`, обе schema и plays; из `live/**` ничего вручную не загружай.
4. Для нового/пересобираемого направления напиши своими словами амбицию. Фундамент строится вместе с тобой:
   - `frame` — миссия, измеримый успех, ограничения, риски и корень;
   - `map_evidence` — актуальная внешняя база;
   - `map` — глобальный roadmap, каждая карточка получает твой вердикт.
   Ничего в CHARTER/TREE не записывается без твоего точного утверждения (G9).
5. На chat-платформе RESULT применяет отдельный свежий writer по `os/adapters/coding-agent.md`. В Codex на репо leg может стать своим writer только после RESULT.
6. Обычный новый чат может начать с `продолжаем`: одна законная работа откроется, несколько дадут выбор, отсутствие работы покажет блокеры/проблемы и planning route.

Сбой чата не теряет сохранённое: `NOW.open_calls` хранит готовые, запущенные, ожидающие и заблокированные продолжения; `issues` — нерешённые проблемы; LOG/history — завершённое. Несохранённый разговор намеренно не является состоянием.

## Ежедневный стратегический чат

Каждый рабочий день открой новый чат и напиши **«начинаем день»**. Это direction-level `day`, а не отдельный управляющий трек.

В начале он заново читает Git и подробно, простым языком объясняет:

- глобальную цель/жёсткие даты и весь roadmap;
- активную локальную цель или отсутствие утверждённой цели;
- что изменилось с прошлого дня и что доказано;
- текущие задачи/исполнительные линии, проблемы и решения;
- прогноз достижения датированной цели (`no_basis`, если честной базы нет);
- что делать сегодня, что можно запустить параллельно внутри локальной цели и какое событие изменит совет.

Весь разговор read-only. Обсуждай, спорь и меняй план как угодно — в Git ничего не попадёт, пока ты явно не скажешь **«сохрани»**, **«запиши»** или **«запускай»** для точной согласованной дельты. Тогда выполняется один атомарный day-leg: RESULT → apply → commit. Структурные изменения передаются владельцу соответствующего play: mission→frame, roadmap→map, активация→shape, остановка/смена цели→review, рассинхрон→repair, дефект OS→maintenance.

После commit можно продолжить этот дневной чат новым leg. `закрываем день` завершает чат; завтра создаётся новый. Workers, reviewers и binding G5 всегда остаются отдельными свежими чатами.

## Одна цель, несколько линий исполнения

`TREE.md` — единственный глобальный roadmap. В `NOW.bet` одновременно не больше одной локальной цели. Будущие цели видны как parked/shaped, но не запускаются.

`NOW.tracks` при необходимости группирует только независимые исполнительные CALL внутри активного бета. Все линии делят WIP-лимит; без бета нет non-recurring треков. Возникшая посторонняя работа сначала попадает в компактный `issues` с route/review trigger, а не становится второй стратегией.

После внешнего запуска явно скажи `запустил <задачу>`: соответствующий CALL станет `running` и не будет предложен повторно. `чат <задачи> потерян/отменён` возвращает именно его; молчание само ничего не перезапускает.

## Регулярно

- раз в неделю: свежий `pulse` по направлениям;
- разъехалось состояние: `почини состояние direction <id>` (`repair`);
- проблема самого workflow: новая maintenance-сессия по `os/MAINTENANCE.md`.

## Чего не делать

- Не держать постоянные worker/reviewer/writer-сессии; дневной чат — советник, не исполнитель.
- Не запускать старый READY CALL, если он не принадлежит активному бету.
- Не редактировать `live/**` руками — только RESULT/writer.
- Не создавать направления или вторые цели «про запас».
