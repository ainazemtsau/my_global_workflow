# Спека любой цели solmax — это текст ядра; тяжёлый разбор не запускается

**Правило направления, принятое картой 2026-09-04 вместе с деревом семи волн.**

Строка, которую нога `shape` копирует в свой `play_check` дословно:

```
triage: trivial — converge OFF — because CORE.md is the spec
```

Та же строка лежит блоком `## triage` в каждой из семи карточек целей
(`g-zara-w0-core-text` … `g-zara-w6-migration`), поэтому `osctl context --for <цель>`
приносит её вместе с целью и разыскивать её не нужно.

**Почему.** §11 плана перехода `work/zaratustra-v2-plan-2026-09-03.md`, первая строка:
«Не запускать converge и спеки по узлам: четыре узла с тяжёлым разбором дали ноль строк
продукта, единственный поставивший шёл лёгким разбором.» Это не гипотеза и не вкус: цена
измерена на закрытой ставке — `knowledge/light-close-throughput-measured.md`,
`history/2026-09-03-s-solmax-zaratustra-v2-review-053.md`.

**Что правило НЕ отменяет.** Оно снимает только `converge`/`converge-arch`/`converge-verify`
как обязательный маршрут готовности цели. Гейты остаются все: G5 (свежее опровержение в
отдельном чате там, где строка требует суждения), G6 (у ставки настоящий список вырезов и
вердикт по каждой линзе), G9 (дерево и одобрения меняются только словом владельца).
Светлое закрытие остаётся исключением для строк, перевыводимых из закоммиченных байтов, —
не общим разрешением закрывать без доказательств.

**Где спека.** Единственная спека продукта — текст ядра в публичном репозитории Zaratustra
(CORE.md и соседние документы), который заводит цель волны 0 и подписывает владелец своим
словом. Отдельных спек по целям направление не пишет.

**Когда правило умрёт.** Если цель, открытая по этому правилу, дважды подряд закроется без
результата владельца — правило перечитывается вместе с §11, а не молча расширяется.
