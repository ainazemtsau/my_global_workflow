- Raw event, durable fact and decision are separated because the owner explicitly wants later
  dynamic chains. Without this, the editor button or future floorboard would directly command
  movement and would have to be torn out for GOAP.
- The replaceable policy port returns one next intention/action. It has no world-state ontology,
  action catalog, preconditions, effects, costs or stored plan. A test-only double proves the seam;
  production still has exactly one reaction.
- One occurrence acknowledgement is necessary to preserve the already accepted rule «fact expires,
  not erased on arrival» without sending the host to the same listening point forever. It is local
  memory, not a fact warehouse.
- The editor panel reads the true path and submits the true event. A debug-only destination setter
  would make testing easy while testing the wrong architecture; it is therefore explicitly banned.
- Odin would add an uninstalled dependency for behavior already supported by the checked-in custom
  editor. The choice is reversible presentation, not a ban on Odin later.
