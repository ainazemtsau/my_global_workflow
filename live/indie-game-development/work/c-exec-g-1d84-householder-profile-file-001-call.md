Выбранный маршрут дешевле всех трёх, которые ему показывали:

1. **Схемы НЕТ и валидатора НЕТ** — ни платного, ни бесплатного. Библиотек проверки схем не ставить.
2. **Профиль — обычный JSON**, читается уже стоящим `com.unity.nuget.newtonsoft-json` `3.2.1`
   (`Packages/manifest.json:22`).
3. **Описание формата — документ плюс один настоящий рабочий профиль образцом.** Схема как машинный
   артефакт не заводится: подписанная владельцем карточка требует «описание формата», а не схему.
4. **Отдельного слоя проверок не создаётся. Разрешение ссылок при старте И ЕСТЬ проверка** — имя, не
   разрешившееся в зарегистрированный набор, не даёт хозяину подняться.
5. **Его довод, и он несущий:** набор способностей растёт КОДОМ через названный шов (`t-host-6`),
   поэтому известен только в рантайме. Статическая схема потребовала бы перегенерации при каждой новой
   способности. Разрешение при старте не устаревает никогда.

   Newtonsoft по умолчанию молча игнорирует незнакомые поля и оставляет отсутствующие в значении по
   умолчанию — тогда опечатка ассистента не роняет старт, и «замечу при старте» перестаёт быть
   правдой. Это настройка уже стоящего Newtonsoft, ноль новых зависимостей; её собственная ошибка
   называет имя, путь, строку и позицию — этим же закрывается «место ошибки».
