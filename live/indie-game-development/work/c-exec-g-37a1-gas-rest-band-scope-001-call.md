диспозиция.

**Существующая «проверка» этой ветки поддельная, и это хуже, чем сообщил возврат.**
`tests/GasCoopGame.Core.Tests/Field/Voxel/G37QuantizationBandTests.cs:92-108` берёт заваренную
комнату из одной клетки, проверяет `OpenFaceCount == 0` (то есть грани нет вовсе), а затем **от руки
дописывает строку показаний** `new G37BandReading(conductivity: 0, drivingDifference: BaseMass,
accumulatedTransfer: 0, carryAtRest: 0)`. `carryAtRest: 0` не измерено — его вписал автор теста, и
измерить его там нечем, потому что грани нет. Комментарий рядом утверждает, что «оба факта измерены
на настоящем поле». Это ровно тот класс, который стоячим законом владельца запрещён как доказательство
поведения.

**Почему ветку нельзя просто дописать тестом — проверено по коду, а не предположено.** Состояние
«грань накопила ненулевой остаток, затем потеряла проводимость» в этой ноге недостижимо ПО
ПОСТРОЕНИЮ, а не по недосмотру:

- `Assets/GasCoopGame/Core/Field/Voxel/VoxelField.cs:47,320,333` — массив `_faceConductivity`
  объявлен `readonly`, выделяется по `_openFaceCount` и заполняется снимком с сетки ОДИН РАЗ в
  конструкторе. Ни одной записи в него вне конструктора в файле нет (единственные другие вхождения —
  чтения на `:1239`, `:1669`, `:1782`);
- `VoxelField.cs:818-827` — единственный похожий шов `NotifyConductivityChanged` только БУДИТ грань
  («changes NO mass/bias/carry»), значение проводимости не меняет и закрытую грань отклоняет
  исключением;
- накопление идёт как `acc = |Δφ|·cond + carry`, поэтому при `cond == 0` накопитель равен `carry` и
  грань не может накопить остаток с нуля. Значит и «открытая грань с `cond == 0` от такта 0» этого
  состояния не даёт.

Итог: у живого поля проводимость открытой грани неизменна до конца сессии. Чтобы построить переход,
нужен шов, меняющий топологию на живом поле, — а это авторитетный `TopologyCommit` с ревизией и точной
mask-delta, то есть ядро задачи `t-7`. Это не «минимальный нетповеденческий тестовый носитель», и
доказательство против наспех сделанного поддельного перехода было бы ложной уверенностью.

**Почему правило при этом справедливо существует.** `VoxelField.cs:838` держит грань активной при
ненулевом остатке (`_faceFluxCarry[i].IsActive`). Застрявший остаток на закрывшейся грани означает,
что поле никогда не приходит к `ActiveFaces == 0`, то есть вечную сетевую дельту на обеих машинах —
удар ровно по единственному жёсткому требованию владельца. Правило нужно; оно нужно в `t-7`.
