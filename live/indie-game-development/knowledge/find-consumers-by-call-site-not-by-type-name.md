# Потребителей типа ищут по месту вызова, а не по имени типа

**ЗАМЕР.** Нога `c-exec-g-5a7c-bedrock-boundary-1-001` переносила три типа в отдельную сборку.
Дописать ссылку пришлось **семи** сборкам, а не пяти. Две — `TunnelCrew.Profiles` и
`TunnelCrew.Networking` — берут типы через `out var`: **имя типа встречается в их файлах НОЛЬ раз.**

Нашёл их только компилятор, ошибкой `CS0012`.

## Что из этого следует

**Текстовый поиск по имени типа даёт ЛОЖНОЕ «потребителей больше нет».** Это не редкий случай и не
экзотика: `out var`, `var`, лямбды и цепочки методов прячут имя типа штатно.

Работает поиск **по местам вызова**: имя метода (`TryFindRoomAt`) в тексте есть даже там, где тип
выведен. Это и есть способ подмести класс целиком, а не первый его случай.

## Почему это ещё и довод против самописных сканеров

У нас записано правилом: самописный сканер как улика запрещён. Здесь видно, почему именно.
Сканер по имени типа нашёл бы пять сборок, доложил бы «всё», и сборка встала бы после слияния.
**Компилятор нашёл семь и не может ошибиться в эту сторону.**
