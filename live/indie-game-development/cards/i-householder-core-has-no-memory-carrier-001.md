## issue
**ЯДРО ХОЗЯИНА РАСШИРЯЕТСЯ ТОЛЬКО НАПОЛОВИНУ, И НЕРАСШИРЯЕМАЯ ПОЛОВИНА — ЭТО ПАМЯТЬ.** Проверено чтением байтов на опубликованной голове `2f7f2e87`: 14 агентов, пять линз, 30 сырых находок; восемь отобраны по силе и отданы отдельным агентам с заданием ОПРОВЕРГНУТЬ — **ни одна не отбита**. Остальные 22 попытку опровержения не проходили и уликой здесь не считаются.

**ЧТО ЗАЛОЖЕНО ВЕРНО и переделывать не придётся.** Ядро правил не знает про движок — поиск `UnityEngine` по `Core/Householder/` и `Core/Situations/` даёт ноль попаданий, шаг хозяина есть чистая функция «память + вход → новая память». Реакция — данные, а не код: `HouseholderReaction.cs:16`, шестая реакция въезжает вызовом `catalog.With(...)` (`:134`) без правки веток, и тест это уже делает на живом продакшн-каталоге. Каталог подменяем снаружи (`HouseholderWalkTuning.WithReactions`, `Householder.cs:727`). Числа вынесены в ассет (`HouseholderWalkSettings.asset:17-21`). Распорядок дня авторится файлом. Шов под собственную политику решений ОБЪЯВЛЕН — интерфейс `IHouseholderDecisionPolicy` (`Householder.cs:451`).

**ЧТО НЕ РАСШИРЯЕТСЯ — пять мест, каждое с ценой.**

1. **Носителя долговременной памяти нет вообще.** Единственное растущее число — `LastFactOccurrenceId` (`Householder.cs:961`), и оно бирка сопоставления, а не величина. Поиск `++`/`+= 1` по всем 1702 строкам даёт одно попадание — шаг по маршруту. Пространственная память — ОДНА перезаписываемая точка `_attentionPoint` (`AuthoritativeHouseholder.cs:139-140`), затираемая каждым шумом (`:269-270`); собственный комментарий файла: «It is remembered until the next noise replaces it». Истечение срока стирает факт в ноль (`Householder.cs:1052-1056`), следа «это уже было» не остаётся. Требования «шкала безумия» и «где они чаще ходили» не имеют носителя ни одного.

2. **САМОЕ ДОРОГОЕ МЕСТО: форма памяти.** `HouseholderLocalMemory` — фиксированная структура из 13 полей с позиционным конструктором (`Householder.cs:913-941`) и ПЯТЬЮ местами сборки внутри `Step` (`:1236, :1289, :1350, :1433, :1603`), плюс публичный конструктор (`:888-911`). Любое будущее желание владельца проходит через неё: шкала — новое поле, счётчик мест — новое поле, история — новое поле, два факта сразу — замена поля на список. Каждый раз одна и та же правка семи мест плюс тесты. **Цена растёт с каждой построенной ногой, а не стоит на месте.**

3. **Кратковременная память держит РОВНО ОДИН факт.** Поле `NoticedFact` (`Householder.cs:955`) не список. Второй факт другого рода: в правилах — `throw new InvalidOperationException("Different simultaneous Householder reactions are outside this single-fact PROBA")` (`:1072-1081`), в собранной игре — молча не слышится (`AuthoritativeHouseholder.CanHear:368-373`). Сценарий владельца дословно («ставит чайник, обжигается, слышит звук, приходит доставка») — три факта разного рода; сегодня он падает на втором. **Эта половина уже куплена открытой задачей `t-react-2`.**

4. **Хендлер на СОЧЕТАНИЕ невыразим.** Реакция ищется по ОДНОМУ скалярному ключу линейным циклом с возвратом первого совпадения: `HouseholderReaction.cs:142` (событие), `:160` (факт), `:179` (причина). Ни одна сигнатура не принимает набор, маску или предикат. Условие «И» требует правки самого вида реакции (`:50-64`, три скалярных ключа) и трёх мест вызова.

5. **Политика решений ФИЗИЧЕСКИ НЕ ЗАПУСКАЕТСЯ В ИГРЕ.** `AuthoritativeHouseholder.cs:234` зовёт двухаргументный `Step`, который жёстко подставляет единственную политику (`Householder.cs:1024`); поля или параметра для своей политики у приёмника НЕТ. Трёхаргументный `Step` вызывается только из тестов (`HouseholderTests.cs:266`). Шов под «своё поведение» есть на бумаге — любая написанная политика сегодня работает только в тесте.

6. **Новый источник требует правки ДВУХ таблиц.** Новый вид ситуации: ветка в `WorldSituationNoise.Of:72-86` и ранг в `Loudness:154-169` — без ранга он получает 0 и не побеждает никогда, то есть не доедет вообще. Плюс за такт в хозяина уходит ровно один раздражитель (`CarryWorld.cs:137-138`).

7. **Реакции файлом не авторятся вообще.** Продакшн-каталог собран КОДОМ (`HouseholderReaction.cs:200-272`), пути из JSON к нему нет. Файлом авторится только распорядок, и только из двух готовых умений: `"ability": "walk-route"` разбирается switch-ом (`HouseholderProfileLoader.cs:43-50`). Новое умение = член перечисления + ветка разборщика + ветки правил (`Householder.cs:761, :779, :1206`). Памяти между сессиями нет и точки входа для неё нет: мир создаётся заново на каждом старте сервера (`NetworkWalkerCourier.cs:50`).

**ОЦЕНКА ОБЪЁМА, ориентир — вчерашняя задача про каталог реакций.** Подключить политику в игру и убрать бросок — примерно как она, может меньше. Память с одного факта на набор — раза в три-четыре больше, и половина уже куплена `t-react-2`. Многоканальный вход — примерно как две таких задачи. **Долговременная память — это не задача, это отдельная волна:** у неё нет ни структуры, ни входа наблюдений (позиции игроков в хозяина не подаются вообще), ни выхода наружу, ни сохранения. Это постройка с нуля, а не расширение.

**ПРЯМОЕ СЛЕДСТВИЕ ДЛЯ ПОДПИСАННОЙ СТАВКИ.** `bet-g-5a7c-wave-2` `## approach` дословно запрещает то, что владелец теперь требует: «НЕ входит: подписчики, история событий, ситуация, пережившая тик, весовое взвешивание приоритетов, любой общий фреймворк под источники». Его живое слово 2026-08-11 старше по авторитету, но текст ставки этого ещё не знает — и ни одна нога не имеет права примирить их молча.
## review_when
**НЕМЕДЛЕННО, а не на ревью волны.** Владелец назвал срок сам: «в конце волны я хочу как минимум ядро вот этого хозяина». Ставка подписана на семь задач при потолке восемь, и её `## approach` прямо запрещает часть требуемого — примирить это может только пересборка дорожки `householder` с его подписью, то есть нога `shape`/`review`, а не наряд и не улика.

До этой ноги: ни один наряд по хозяину не пишется без сверки с `knowledge/core-is-extended-never-rewritten.md`, и каждый обязан назвать в `boundaries` результат теста «ДОБАВИТЬ или ПРАВИТЬ» для каждого места, которое открывает.

Отдельной строкой в пересборку: `t-react-2` уже выдан и вскрывает ровно те пять мест сборки памяти, которые дороже всего трогать дважды. Решение «чинить форму памяти в ней или отдельной задачей» принимается ДО расписки исполнителя, иначе те же семь мест будут правиться два раза.
