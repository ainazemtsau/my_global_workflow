## done_when
**ОДНА КОМАНДА ДЕЛАЕТ СБОРКУ С ИМЕНЕМ, И В НЕЙ НЕТ НИЧЕГО ЧУЖОГО.**

**СБОРКА ОДНОЙ КОМАНДОЙ УЖЕ ЕСТЬ — ЗАМЕР НАРЕЗКИ, И ПЛАН ЭТОГО НЕ ЗНАЛ.** `tools/unity-build.ps1`
зовёт `-executeMethod TunnelCrew.Editor.PlayerBuildCommand.BuildWindows64`
(`Assets/Editor/PlayerBuildCommand.cs`), кладёт `Builds/StandaloneWindows64/TunnelCrew.exe`, пишет
`Logs/unity-gate/player-build.json` из настоящего `BuildReport` и возвращает 0 только на
`Succeeded`. Сцены берутся из Build Settings, не дублируются в коде.

1. **НОМЕР ВЕРСИИ — ДАТА ПЛЮС КОММИТ — И ПАПКА ВЫДАЧИ.** Это `DefaultOutputDir` / `ExecutableName`
   в `PlayerBuildCommand.cs` плюс аргумент скрипта. **ПОРОГ: если появляется новый скрипт сборки —
   прогноз волны был неверен, скажи это фактом.**

2. **ЧЕТЫРЕ ГОЛОВНЫХ ТЕСТА ПЕРЕЕХАЛИ С ПОСТАВОЧНОГО ПРОФИЛЯ НА ТЕСТОВУЮ КОПИЮ.** Улика
   `i-mechanism-tests-stand-on-disposable-shipped-content-001`: удаление четырёх дел из поставочного
   профиля роняет тесты механизмов. Тесты не должны зависеть от расходного содержимого.
   Помни: **домов у тестов два** — headless гоняет `tests/TunnelCrew.Core.Tests/**`, Unity-тесты
   живут в `Assets/Tests/**`; поиск по одному даёт ложный ноль.

3. **В СБОРКЕ НЕТ ЧУЖИХ ДЕМО-КЛИПОВ Feel.** Упоминания Feel живут в трёх сценах, включая
   `IntegratedHouse.unity`. Своих аудиофайлов в `Assets/TunnelCrew` сегодня ноль — значит вычистить
   надо до того, как задача `t-six-events-make-a-sound-1` положит свои.

4. **НИ ОДИН ТЕСТ НЕ ГАСИТСЯ.** `tools/hygiene.ps1:363-376` запрещает это абсолютно. Замер до
   волны: headless `819 / 819 / 0` — перемерь у своей головы и назови своё число.

**ПРИЁМКА: прогон (сборка зелёная, `BuildReport` говорит `Succeeded`) плюс живая проба — exe
запускается на машине, где проекта нет.**
