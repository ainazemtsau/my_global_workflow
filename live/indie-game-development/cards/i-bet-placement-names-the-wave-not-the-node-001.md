## issue
**ПОЛЕ `_bet` ЗАПОЛНЯЛОСЬ ID ВОЛНЫ ВМЕСТО ID ЦЕЛИ, И ИЗ-ЗА ЭТОГО НИ ОДНА ЖИВАЯ ЗАДАЧА НЕ
ПОПАДАЛА В РАБОЧИЙ НАБОР.** Перемерено обзором восьмой волны 2026-08-30 первой рукой; сам
перекос уже исправлен в живых карточках, эта улика — про то, почему его никто не заметил.

**ЗАМЕР.** `osctl context` берёт задачу условием `head["_bet"] == node` (`osctl.py:1035`, ветка
«ставку берут целиком со списком задач»), где `node` — id ЦЕЛИ. Схема пишет то же самое
(`os/schema/direction-files.md`, шаблон task: `_bet: g-xxxx`), и подсказка самого `check` пишет
то же самое — «card set --field _bet --value <id цели>». Но по всем карточкам задач счёт был
такой: **28 несут `g-5a7c`** (все старые), **50 несут `bet-g-5a7c-wave-N`**, 5 не несут ничего.
Результат: `osctl context --for g-5a7c` возвращал рабочий набор из 7 файлов, и все **28 живых
задач** стояли в строке «НЕ ВКЛЮЧЕНО» — включая девять собственных задач идущей волны.

**ПОЧЕМУ `check` МОЛЧАЛ, И ЭТО ГЛАВНОЕ.** Он проверяет только НАЛИЧИЕ поля:
`if head.get("_kind") == "task" and not head.get("_bet")` (`osctl.py:1155`). Что значение
РАЗРЕШАЕТСЯ в живую карточку — не проверяется вообще. Поэтому пять задач без ставки он называл
честно, а пятьдесят задач с неверной ставкой были для него неотличимы от правильных.

**ЦЕНА, КОТОРАЯ УЖЕ ЗАПЛАЧЕНА.** Улика `i-live-cards-point-at-closed-and-empty-bets-001` описала
следствие («двенадцать задач не доедут до нарезки»), но назвала причиной членство в ставке и
поэтому оценила беду вчетверо меньше настоящей: не двенадцать, а все двадцать восемь. Ремонт
2026-08-30 по той же причине не стал чинить поле — счёл, что проставить `_bet` значит задним
числом записать задачу в состав ставки. Схема говорит другое: `_bet` — это МЕСТО карточки, и
комментарий в самом `osctl.py:361-367` называет ровно этот класс отказа: «заведённая по правилам
задача не попадала в рабочий набор следующей ноги и просто терялась».

**ЧТО ОСТАЛОСЬ.** Живые карточки исправлены. Закрытые — нет: 50 карточек в `closed/` по-прежнему
несут id волны в `_bet`. Для рабочего набора это безразлично (закрытые не собираются), но
переоткрытая карточка вернётся невидимой.
## review_when
`maintenance` — вместе с уже стоящей парой `i-fourteen-delivered-legs-had-no-card-001` и
`i-thirteen-closes-left-no-result-in-history-001`: у всех трёх один класс — состояние расходится
с продуктом, и ни один механический сторож этого не видит. Требуемая правка узкая:
`osctl check` обязан назвать `_bet`, который не разрешается в живую карточку цели, — так же, как
сегодня называет отсутствующий. Плюс решить, чинить ли `_bet` в закрытых карточках или оставить
как есть с известным следствием при переоткрытии.
